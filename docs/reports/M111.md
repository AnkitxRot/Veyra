# M111 — Low-resource host profile

## Goal
One weak host (2–4 GB RAM, 2 cores, Linux) serves many users: idle users cost
about zero RAM, active users get small sandboxes, overload returns "busy,
retry" instead of swapping.

## Changes
- `backend/src/resourceProfile.ts`: pure `HOST_PROFILE=auto|low|standard`
  selection and derived caps. Wired into `config.ts`; explicit env vars win.
  New env: `SANDBOX_STOP_AFTER_MS`, `MAX_GLOBAL_RUNS`, `HOST_MEM_RESERVE_MB`,
  `SANDBOX_MEMORY_MB`, `SANDBOX_CPU_MILLIS`, `SANDBOX_PIDS_LIMIT`.
- `execution/sandbox.ts`: two-tier idle. Tier 1 `docker stop -t 2` keeps the
  container and network (`stopped` entry, no gate slot, not counted against
  `maxSandboxes`); tier 2 `rm -fv` after `sandboxIdleTimeoutMs`. Ensure on a
  stopped entry uses `docker start`, falling back to recreate on failure.
  Soft stop runs under the per-project lifecycle lock and skips projects with a
  lifecycle op in flight, live collaborators, open terminals or a live debug
  session.
- Admission: free RAM < sandbox memory + reserve stops the LRU idle sandbox
  (idle ≥ 15 s); otherwise `ApiError(503, server_busy)` with `Retry-After`.
  The sandbox-cap error is now also `server_busy` (message unchanged).
  `sandboxRun` re-throws it so REST returns 503 and `/ws/execute` sends
  `{type:"error", code:"server_busy"}`. `globalRunGate` caps concurrent
  run/build/install processes (default = CPU count).
- Telemetry: one batched `docker stats` per tick, skipped while in flight
  (`getAllContainerStats()`); per-project `getContainerStats` stays the cache
  reader.
- Footprint: SQLite `synchronous=NORMAL`, `cache_size=-2000`,
  `temp_store=MEMORY`, `mmap_size=0`; `NODE_OPTIONS=--max-old-space-size`
  (`NODE_HEAP_MB`, default 256) in `Dockerfile.app`; hashed `/assets` served
  `immutable, max-age=1y`; TTL sweeps for comment limiters and preview probe
  cache.
- Observability: `veyra_host_free_memory_bytes`, `veyra_sandboxes_running`,
  `veyra_sandboxes_stopped`, `veyra_gate_occupancy{gate}`,
  `veyra_host_profile{profile}`.
- Ops: `deploy/docker-compose.prod.yml` `HOST_PROFILE` + `mem_limit`; README
  "Low-end host".

## Risks
- 256 MiB can be tight for tsserver plus `npm install`; env overrides remain.
- Docker Desktop on Windows adds ~1–2 GB of VM overhead; use Linux.
- Active concurrency stays RAM-bound (~6 on 2 GiB). Idle users cost only disk.
- Backend restart: reconcile adopts running containers and `exited` ones
  (as stopped entries, resumable with `docker start`).
- Soft stop skips projects with a `sandboxRun` in flight (per-project exec
  counter); git execs via ensure are not covered.
- Not verified here: the manual `HOST_PROFILE=low` Docker run (3 projects
  idle 3 min, resume < 2 s).
